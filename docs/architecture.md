# 保存・時点管理

SQLiteの`races`は12桁キーYYYYMMDDjjrrで日付・場・Rを識別する。`snapshots`はレース×種類×ソース×内容ハッシュの履歴。`auxiliary`はモーター成績・節別履歴を同様に保持する。

日時はUTCに正規化し、元CSVはRAWのまま残す。タイムゾーンなしの公式/OpenAPI締切日時はJSTとして解釈する。

- `source_at`: 取得元の記録時刻。無ければNULL（締切5分前だったと推定しない）。
- `first_seen_at`: こちらがバイト列を受信し終えた時刻。
- as-of参照は両方が予測時刻以下のものだけ。履歴取得日が遅いデータを当時の実運用予測に使わない保守的な方式。
- 同じ値でも取得元のスナップショット時刻が変われば別履歴。ファイル全体と各行は別々に内容ハッシュ化する。
- 結果の訂正は新たな履歴。最新の可視状態を選び、レースを二重に集計しない。
- OpenAPIは未確定結果の空の6艇オブジェクトを返すことがある。着順/状態が全て空なら未確定と扱う。
- 公式HTMLはRAWのみ。未検証のパーサーで公式値を捏造しない。

## RAWからの再構成

fetchesがRAWのSHAと取り込み済みフラグを記録する。再構成先は空の別ディレクトリ。元の受信時刻を保持し、新しい再構成時刻をデータ利用可能時刻に置き換えない。

## 欠損監視

締切3分前以降に展示・オッズを検査。結果/払戻は締切45分後以降に遅延・欠損扱い。午前に未開催レースの結果がないことを障害にしない。欠場が結果で確認済みの場合に限り、その艇の展示・未発売組番を必須から除外する。未来の欠場結果を締切前に使わない。

オッズの0は元の数値として保存し、空欄と分ける。0は購入可能な倍率とは扱わない。オッズの発売対象判定を予測モデルに載せるときは、購入時点に判明している欠場情報の専用取得が必要。

## 未実装の境界

このバージョンはデータ基盤。学習モデル、予測API、モデル昇格、収支レビューはスキーマだけの準備段階で実行処理はない。会場・選手・モーターのカルテは統計であり因果的な能力推定ではない。単一レースから「モーターの過小評価が原因」と断定しない。
