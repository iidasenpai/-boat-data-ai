# ボートレース データ収集・カルテ基盤 v0.1

まず収集基盤を作る、という合意に基づく第一段階です。予測AI・期待値による買い目・再学習モデルはまだ搭載していません。

## 今回動くもの

- 全国24場を含む日次OpenAPIとBoatraceCSVの自動取得。実際に開催している場のレースを保存。
- 出走表、今節14スロット（コース・枠・ST・着順）、枠番別10走、全国・当地近況、モーター成績・履歴。
- 展示、オリジナル展示、得点率、気象、3連単オッズ、結果、払戻のスナップショット。
- RAWの内容ハッシュ保存、取得ログ、SQLiteへの履歴追加、訂正履歴保持、二重集計防止。
- 選手カルテ、会場カルテ、使用期別モーターカルテの再生成。
- 取得遅延・必須項目欠損・結果ソース不一致の監視。
- スマホ幅対応の閲覧画面。これは出力時点の集計で、データが更新されるまで変わりません。
- 選択したレースの公式出走表・直前情報・オッズ・結果HTMLを証拠として保存。
- 元データから別DBへ再生成、SQLite整合性確認、DB＋RAWを含むバックアップ。

## 最短の起動方法（常時動くPC / サーバー）

Docker と Docker Compose のある環境で、このフォルダを開いて実行します。

```sh
docker compose up -d --build
```

画面は `http://localhost:8080`。起動後に作成・更新されます。収集は3分間隔、詳細事前情報は1時間ごと。再起動後も自動再開し、データはホストの `data/` に残ります。ポートはローカルに限定しています。スマホから使うには、設置先を決めて認証付きのアクセスを設定する必要があります。

停止は `docker compose stop`、再開は `docker compose start`。データは停止だけでは削除されません。

**設置先は未決定なので、この納品時点で24時間の収集サービスが稼働しているわけではありません。** iPhone単体ではPython/Docker収集処理を常駐できません。ZIP内のソースと検証済みデータを、選んだ設置先へ配置します。

## Pythonのみで動かす場合

Python 3.11以降。外部Pythonパッケージ不要。下記はプロジェクト直下で実行します。

```sh
python -m boatdata --data data collect --date 2026-10-01
python -m boatdata --data data report --date 2026-10-01
python -m boatdata --data data serve
```

Linux / macOSの常時収集：

```sh
python -m boatdata --data data daemon
```

同じデータディレクトリで二つのdaemonを動かすことをロックで防ぎます。Windowsで常時動かす場合はDockerを使ってください。一回収集・閲覧・バックアップはWindowsでも動かせます。

### 補助コマンド

```sh
# 公式の照合用HTMLを4ページ保存（自動パーサーではありません）
python -m boatdata --data data official --race 202609291510

# SQLiteのオンラインバックアップ＋全RAWをZIP化
python -m boatdata --data data backup --output backups/boatrace-backup.zip

# RAWから空の別ディレクトリにDBを再生成
python -m boatdata --data data replay --to rebuilt-data

# ローカルファイルの取り込み
python -m boatdata --data data import --source openapi --file day.json
python -m boatdata --data data import --source race_cards --file cards.csv

# 当時こちら側で取得できていた情報だけの集計
python -m boatdata --data data report --date 2026-09-29 --as-of 2026-09-29T18:00:00+09:00

# 自動テスト
python -m unittest discover -s tests -v
```

`--as-of` は実際の受信時刻を基準にします。今回10月1日に後から取得した9月29日のデータは、9月29日時点の集計には入りません。歴史データを学習用に使うことと、本当に当時取得していたことを証明することは別です。

## 保存場所

| 場所 | 内容 |
|---|---|
| `data/boatrace.sqlite` | レース、出走表・直前・オッズ・結果の履歴、補助データ、カルテ履歴 |
| `data/raw/` | 内容ハッシュで保存した未加工バイト列（削除・上書きしない） |
| `data/dashboard/index.html` | 閲覧画面 |
| `data/dashboard/monitor.json` | 欠損・遅延レポート |
| `data/dashboard/profiles.json` | 全カルテ数値 |
| `data/heartbeat.json` | 常時収集プロセスの最終処理時刻と状態 |
| `data/backups/` | daemonが日次作成するDB＋RAWバックアップ |

同じディスク上のバックアップだけでは、そのディスク自体の故障には対応できません。設置時に外部へのバックアップも決めます。「永久保存」は保存方針であって、現在の未設置状態で無期限の保持を保証する意味ではありません。RAWの自動削除はありません。

## カルテの内容と扱い

選手：実際のコース別、会場別、会場×コース別、風速別、F本数別、直近10/30走、180/365日、平均ST・ばらつき、展示→本番ST差、展示F、本番F、勝った際の決まり手。

会場：30/90/365日、コース別1着/2連/3連率、風速×コース、風向、波高、季節、R番号、当日ここまでのコース傾向。当日の件数と長期側への平滑化値も保持。

モーター：場＋番号＋使用期で分離、直近20走、全走、使用者、実コース別、使用期確認の有無。使用期未確認は `unknown` と明示。選手能力を補正した機力スコアは未実装で、空値を表示します。

割合には分母となる件数を必ず付けます。少数のデータは20走相当の事前分布で平滑化します。選手のコース成績は全選手の同コース、選手の会場×コース成績は本人の全場同コースを参照します。平滑化強度20は暫定の集計設定で、AIによって最適化した数字ではありません。欠場は走数に数えず、F・転覆など実際に出走した非入着は残します。展示Fを除外・罰則スコア化しません。

`waku10` は今回と同じ**枠番**での10走です。実際の進入コースとは区別し、RAWと専用スナップショットを保持します。今節14スロットも取得時点の出走表に含まれるまま保持し、全走を古い予測へ逆流させません。

## 制限・次段階

- 公式は現在、選択レースの照合用HTML保存まで。全レース公式自動照合・公式長期ダウンロード取り込みは未実装。
- オッズはCSV提供のスナップショット。自前の10分/3分/1分前連続取得は未実装。
- 会場の未登場は「開催未確認」。公式日程による非開催確定は未実装。
- 開催初日・安定板・進入想定など、取得元に無い項目を推測して埋めません。
- 日別モーター履歴は、その日に基準節終了分が無ければ404のことがあります。得点率・オリジナル展示も常に全場全Rにはありません。
- モーターの展示順位・選手能力を補正した機力、潮汐と向かい/追い風の変換、カルテに文章を付ける処理は次段階。
- 予測固定用のDBテーブルと変更禁止トリガーは作成済み。予測確率・購入判断・自動採点/回顧・Champion/Challengerは次段階。
- HTTP取得失敗はログに残し、次回再試行します。daemon停止自体の外部通知・外部ストレージ・複数日耐久試験は設置後に確認。

まず常時稼働させ、取得遅延、欠場、訂正、場別の配信差、バックアップ復元を数日確認してから予測モデルに進みます。
